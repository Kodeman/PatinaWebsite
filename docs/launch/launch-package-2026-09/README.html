How to use it this week

  1. Read the book together. Select the first appropriate client contacts and choose the actual first-send date, T0.
  2. Review EMAIL-01 in Leah’s voice. Use C01 or C03 with SOCIAL-01 after the first replies have been read.
  3. Confirm the live joining experience in a normal browser and who is handling replies/applications. Automated GET checks from the preparation environment returned 403; no fresh production form submission or email test was performed for this package.
  4. Read the first three Madison target notes. Dispatch individually after the personal first wave; regional pitches wait for an actual local connection.
  5. Put the weekly review and monthly member question on the founders’ calendar when the campaign starts.

What is finished

Finished: strategy and copy drafts, researched target routes, six image exports, editable creative masters, a motion production brief, presentation/guide HTML, PDFs, link registry, and blank operating templates. Nothing has been sent, scheduled, purchased, or published. Additional founder and partner photography can follow the first campaign wave.

The first-person letters are prepared editorial language for Kody and Leah, not verbatim quotations. The six-week acquisition targets and workload allocations are recommendations, not claimed results or accepted commitments. Day 7/21/monthly letters are ready to use manually; this package has not installed a marketing automation.

Files and portability

Open launch-book.html or creative/index.html in a browser. HTML, images, fonts, and PDFs work from the extracted package. Markdown and CSV remain editable in ordinary text and spreadsheet applications. The references/ folder contains dated snapshots and original provenance context. Historical wording in those snapshots does not supersede the latest messaging system or the exact public caption: Illustrative imagery — awaiting partner photography.

The package contains no customer export, account credentials, or private client details. Reference documents may mention repository source paths; those are provenance pointers, not required files for viewing the book or artwork.

See quality-checks.md for the actual render, link, and content checks completed at handoff. build-package.py regenerates the readable document HTML; render-package.mjs regenerates PDFs and presentation checks with the repository’s Playwright installation.
